# Setting up slurm

At this point, all nodes are running tailscale.



# 1. Setup control groups 


Slurm needs ability to bind cores
- cgroup_enable=cpuset`: enables the cpuset controller, which pins a process group to specific CPU cores (and memory nodes).
- Slurm uses it for core binding, so a job that requests 2 CPUs is confined to 2 cores.


Slurm needs to be able to track and kill jobs exceeding RAM cap
- cgroup_enable=memory: enables the memory controller, which tracks and caps RAM usage per cgroup. 
- cgroup_memory=1: an older/Pi-specific flag that does the same thing as the previous one. The Pi firmware historically shipped with memory cgroups off, and this flag was the toggle. Having both is redundant on newer kernels but harmless.
- swapaccount=1: extends memory accounting to include swap, so limits cover RAM plus swap rather than RAM alone.

Add the following to `/boot/firmware/cmdline.txt` 

```
cgroup_enable=cpuset cgroup_memory=1 cgroup_enable=memory swapaccount=1
``` 

Reboot the system after this with `sudo reboot`.

# 2. Connecting devices

Install munge on all nodes: `sudo apt install munge`

Copy munge keys from the head node to compute nodes:
```bash
sudo cp /etc/munge/munge.key /tmp/munge.key
sudo chown $USER /tmp/munge.key
scp /tmp/munge.key john@john-macbookair:/tmp/
scp /tmp/munge.key john@john-desktop:/tmp/
rm /tmp/munge.key
```

On each compute node, put the munge key where it belongs and give correct access. Then, restart and enable munge.
```bash
sudo mv /tmp/munge.key /etc/munge/munge.key
sudo chown munge:munge /etc/munge/munge.key
sudo chmod 400 /etc/munge/munge.key

sudo systemctl restart munge
# enable munge
sudo systemctl enable munge
```

Enable munge on the head node:
```
sudo systemctl enable --now munge
```

Check that munge can access each node. This should be error-free, and then make sure that your uid and gids match between nodes.
```bash
munge -n | ssh john@john-desktop unmunge
munge -n | ssh john@john-macbookair unmunge
```

# 4. Run into problems with Slurm version compatibility
**This is a problem...** The head node version must be >= worker node Slurm version but not more than 2 major releases ahead ([source](https://slurm.schedmd.com/upgrades.html#compatibility_window)). This is more than two releases ahead because I'm running ubuntu 22.04 on the workers. 

# 5. Fix problems with Slurm version
I migrated the Raspberry pi to Ubuntu 22.04 server, then repeated all of the other setup steps (tailscale etc). 

# 6. Install Slurm

On Raspberry Pi:
```
sudo apt install slurmctld slurm-client
```

On worker nodes:
```
sudo apt install slurmd slurm-client
```

# 7. Setup Slurm config

Use `slurmd -C` on each of the worker nodes to get node stats:
```
NodeName=john-MacBookAir CPUs=4 Boards=1 SocketsPerBoard=1 CoresPerSocket=2 ThreadsPerCore=2 RealMemory=7882

NodeName=john-desktop CPUs=4 Boards=1 SocketsPerBoard=1 CoresPerSocket=4 ThreadsPerCore=1 RealMemory=32042
```

Insert those node stats at the bottom of `/etc/slurm/slurm.conf` file, but lower the realmemory to be safe.

```
ClusterName=lpcc
SlurmctldHost=john-pi

AuthType=auth/munge
SlurmUser=slurm
StateSaveLocation=/var/spool/slurmctld
SlurmdSpoolDir=/var/spool/slurmd
SlurmctldLogFile=/var/log/slurm/slurmctld.log
SlurmdLogFile=/var/log/slurm/slurmd.log

ProctrackType=proctrack/linuxproc
TaskPlugin=task/affinity
SelectType=select/cons_tres
SelectTypeParameters=CR_Core_Memory

NodeName=john-desktop NodeAddr=<DESKTOP_IP> CPUs=4 Boards=1 SocketsPerBoard=1 CoresPerSocket=4 ThreadsPerCore=1 RealMemory=29000
NodeName=john-MacBookAir NodeAddr=<MacBookAir_IP> CPUs=4 Boards=1 SocketsPerBoard=1 CoresPerSocket=2 ThreadsPerCore=2 RealMemory=6800

PartitionName=main Nodes=ALL Default=YES MaxTime=INFINITE State=UP

```

# 8. Set up permissions

Raspberry pi head node:
```
sudo mkdir -p /var/spool/slurmctld /var/log/slurm
sudo chown slurm: /var/spool/slurmctld /var/log/slurm
sudo chmod 755 /var/spool/slurmctld
```

Worker nodes:
```
sudo mkdir -p /var/spool/slurmd /var/log/slurm
sudo chown root: /var/spool/slurmd
sudo chmod 755 /var/spool/slurmd
sudo chown slurm: /var/log/slurm
```

# 9. Turn it on

Pi:
```
sudo systemctl enable --now slurmctld
```
Worker nodes: 
```
sudo systemctl enable --now slurmd
```

Then run 
```
sinfo # check for nodes as the output
srun -N2 hostname
```
Use this sbatch test to write from both nodes to /shared/fast. I ran it a bunch of times, in a row to test the queueing an job submission to multiple nodes

```bash
#!/bin/bash
#SBATCH --job-name=test
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --time=00:02:00
#SBATCH --mem=500 # MB
#SBATCH --output=/shared/fast/jobs/test-%j.out
#SBATCH --error=/shared/fast/jobs/test-%j.err

echo "host: $(hostname)  job: $SLURM_JOB_ID  node list: $SLURM_JOB_NODELIST"
echo "start: $(date)"
echo "whoami: $(whoami)  uid: $(id -u)"
echo "wrote from $(hostname) at $(date)" > /shared/fast/jobs/smoke-$SLURM_JOB_ID.txt
sleep 15
echo "end: $(date)"

```

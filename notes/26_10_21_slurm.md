# Setting up slurm

At this point, all nodes are running tailscale.



# 1. Setup control groups 


Slurm needs ability to bind cores
- cgroup_enable=cpuset`: enables the cpuset controller, which pins a process group to specific CPU cores (and memory nodes).
- Slurm uses it for core binding, so a job that requests 2 CPUs is confined to 2 cores.


Slurm needs to be able to track and kill jobs exceeding RAM cap
- cgroup_enable=memory: enables the memory controller, which tracks and caps RAM usage per cgroup. 
- cgroup_memory=1: an older/Pi-specific flag that does the same thing as the previous one. The Pi firmware historically shipped with memory cgroups off, and this flag was the toggle. Having both is redundant on newer kernels but harmless.
- swapaccount=1: extends memory accounting to include swap, so limits cover RAM plus swap rather than RAM alone.

Add the following to `/boot/firmware/cmdline.txt` 

```
cgroup_enable=cpuset cgroup_memory=1 cgroup_enable=memory swapaccount=1
``` 

Reboot the system after this with `sudo reboot`.

# 2. Connecting devices

Install munge on all nodes: `sudo apt install munge`

Copy munge keys from the head node to compute nodes:
```bash
sudo cp /etc/munge/munge.key /tmp/munge.key
sudo chown $USER /tmp/munge.key
scp /tmp/munge.key john@john-macbookair:/tmp/
scp /tmp/munge.key john@john-desktop:/tmp/
rm /tmp/munge.key
```

On each compute node, put the munge key where it belongs and give correct access. Then, restart and enable munge.
```bash
sudo mv /tmp/munge.key /etc/munge/munge.key
sudo chown munge:munge /etc/munge/munge.key
sudo chmod 400 /etc/munge/munge.key

sudo systemctl restart munge
# enable munge
sudo systemctl enable munge
```

Enable munge on the head node:
```
sudo systemctl enable --now munge
```

Check that munge can access each node. This should be error-free, and then make sure that your uid and gids match between nodes.
```bash
munge -n | ssh john@john-desktop unmunge
munge -n | ssh john@john-macbookair unmunge
```
